# 串口视频播放：电脑推流 → STM32 → ST7789

> 当前默认参数：**1500000 bps / 80×80 / 8 位色 / 等待 ACK**，实测约 17 fps。
> 下文末尾的「更新记录」按时间倒序记录了参数演进过程，早期段落里的 921600 已不是默认值。

## 接线（USB-TTL 串口模块，如 CH340）

| USB-TTL | 单片机 | 说明 |
|---|---|---|
| TXD | PA10 | 模块发 → 单片机收 |
| RXD | PA9 | 单片机回 ACK 用 |
| GND | GND | 共地，**必须接** |
| VCC | 不接 | 不要接，板子自己供电 |

注意：烧录口（ST-Link）和这个串口是两回事，要另接一个 USB-TTL 模块。

## 电脑环境

    pip install -r requirements.txt

## 运行

    python video_to_uart.py 你的视频.mp4 --port COM3 --baud 1500000 --size 80 --depth 8 --loop

1. 先运行上面命令（把 COM3 换成你的串口号，设备管理器里查）。
2. 再按一下单片机上的复位键（RESET）。
3. 方向卡显示 4 秒后，8 秒内检测到视频流就开始播放；否则进弹球 demo。
4. 看完把脚本 Ctrl+C 停掉，10 秒无数据单片机自动回到弹球 demo。

摄像头直播：`python video_to_uart.py CAM:0 --port COM3 --baud 921600 --preview`

## 帧率参考（1500000 bps，ACK 模式）

| 分辨率 | 8 位色（默认） | 16 位色 | 说明 |
|---|---|---|---|
| 120×120 | ≈10 fps | ≈5 fps | 最清晰，2× 放大 |
| 90×90 | ≈17 fps | ≈9 fps | 2× 放大，居中 |
| 80×80 | **≈17 fps** | ≈11 fps | **默认**，3× 放大铺满 |
| 60×60 | ≈17 fps | ≈17 fps | 4× 放大铺满，已被刷屏卡住 |

> 80 和 60 帧率一样（都撞到 51ms 的刷屏上限），所以选 80。
> 想更快只能提 SPI 分频或换通道，见仓库 `docs/03-性能与调优.md`。

想流畅优先选对比强、节奏慢的视频（Bad Apple 这类黑白短片最合适）。

## 常见问题

- 提示打开串口失败：串口号错了，或串口被 Keil/串口助手占用，关掉它们。
- 屏幕停在方向卡不动：脚本没跑起来，或 TXD/RXD 接反了，对调试试。
- 画面卡住不动但脚本在发：波特率两边不一致，检查 `--baud` 和 `usart.c` 里的 1500000。
- 颜色不对（红蓝反了）：视频本身是 BGR，脚本已转 RGB；若仍反，检查 RGB565 打包。
- 画面撕裂/缺块：线太长或波特率太高，降波特率，或把 SPI 分频改 /4 提显示速度。
## 图形版软件（推荐，不用装 Python）

双击运行 `dist\ST7789VideoSender.exe`（约 70MB，单文件绿色版）：

1. 点"浏览"选视频（或点"摄像头"用 CAM:0 直播）。
2. 串口下拉框选你的 USB-TTL（点"刷新"重扫），波特率默认 1500000，分辨率默认 120，色彩默认 8 位。
3. 点"开始推送"，再按单片机复位键，方向卡后自动播放。
4. 日志框会显示帧数和帧率，点"停止"结束。

首次运行 Windows 可能会弹 SmartScreen，点"仍要运行"即可。
自己改过 Python 源码后，重新打包：`pyinstaller --noconfirm --clean --onefile --noconsole --name ST7789VideoSender video_sender_gui.py`

## 2026-11-02 更新

- 默认**按比例居中截取**（cover 模式），16:9 视频取中间正方形，不再拉伸变形；命令行加 `--stretch` 可恢复拉伸。
- 新增**单向模式**（不等 ACK，固定 5fps）：只接了 TX+GND、没接 RX 线时用。命令行 `--no-ack`，图形版取消勾选"等待ACK"。
- 串口打开失败自动重试 3 次并提示排查（占用/重插/换口）。
- 单片机固件改为纯视频版：去掉弹球，上电方向卡 3 秒 → 黑屏无限等流，断流保持最后画面。

## 2026-11-02 晚间更新（卡顿修复）

- ACK 等待从 8 秒缩到 3 秒：ACK 线正常时不受影响，异常时失败恢复快 3 倍。
- 单向模式（关 ACK）改为按线速 pacing：每帧等待 frankly 一帧的传输时间，
  921600 下约 2.7fps 匀速推送，不再堆积延迟。
- 若 ACK 一直超时但画面一点点过来：说明只通了发送方向，检查 RXD→PA9 那根线
  （杜邦线松动最常见）；或直接关掉"等待ACK"用单向模式看。

## 2026-11-02 晚间更新2（降画质提速）

- 分辨率可选 120/90/80/60，默认 80。单片机自动整数放大铺满全屏
  （80→3x、60→4x 正好全屏，90→2x 居中）。
- 921600 下理论帧率：120≈2.7fps，90≈4.4fps，80≈5.4fps，60≈9fps。
- 单片机固件同步更新（驱动加 ShowImageScale/ShowImageAuto），记得重烧。
- 还想更快：波特率改 1500000（两边一起改），80 可到约 8fps。

## 2026-11-02 晚间更新3（1.5M + SPI/4 提速）

- 串口 921600 → 1500000（软件默认 + 单片机 usart.c + .ioc 同步，CH340 一般都支持）。
- SPI1 分频 /8 → /4（18MHz，ST7789 无压力），显示一帧约 0.11s → 0.06s。
- 80 分辨率 @1.5M：线速约 8fps，ACK 模式约 6fps。记得单片机重烧！
- 若个别 CH340 在 1.5M 下丢包（表现为频繁 NACK/重发），退回 921600 即可。

## 2026-11-02 晚间更新4（8位色 + ACK自动降级）

- 新增色彩选项：16位 RGB565（清）/ 8位 RGB332（快，数据量减半，约2x帧率），默认 8位。
  单片机从帧长度自动识别位深，协议不变。80px@1.5M：8位线速约 15fps，ACK 模式约 9fps。
- ACK 连续 3 帧超时，软件自动切换单向模式并提示检查 RXD→PA9 回线，不用手动关 ACK 了。
- 命令行：--depth 16|8（默认8）。
## 2026-11-02 晚间更新5（8位色抖动优化）

- 8 位模式改用量化取整 + Bayer 4x4 有序抖动，饱和度/色调接近原片，不再发灰；纯色不受影响。
- 单片机不用动，这次只换电脑端 exe。

## 2026-11-02 晚间更新6（去白噪点）

- 抖动强度随亮度衰减（暗部只抖 1/4），接近黑的像素直接压成纯黑，白色噪点消失。
- 量化改四舍五入，落在整点上的颜色不再抖。单片机不用动，只换 exe。

## 2026-11-02 晚间更新7（回退抖动）

- 8 位色回到直接截断（无抖动、无压黑），白噪点消失，中间色回到偏平风格。单片机不用动，只换 exe。

## 2026-11-02 晚间更新8（回到 Bayer v1 抖动）

- 8 位色回到全额 Bayer 4x4 有序抖动 + 取整，色彩过渡自然。近看有细噪点属正常，离远看顺。单片机不用动，只换 exe。

## 2026-11-02 晚间更新9（DMA 双缓冲管线）

- 单片机：串口 DMA 双缓冲收 + 显示并行，吞吐从 收+显 之和变成两者取大，80px@1.5M 约 17fps（原来约 10fps）。
- ACK 语义改为校验通过即回，ACK 模式自适应最快；无 ACK 模式 pacing 对齐 58ms 节拍。记得重烧！
- 建议重新勾上等待ACK（RX 线正常的话），现在它比单向更快更稳；RX 不通会自动降级。

## 2026-11-02 晚间更新10（暗部压黑去噪）

- v1 全额抖动保留，只加：原片最亮通道低于 20 的像素直接纯黑。暗底白噪点消失，亮部色彩风格不变。单片机不用动，只换 exe。

## 2026-11-02 晚间更新11（默认 120 降噪点）

- 默认分辨率 120：2 倍放大，抖动颗粒小一半，细节多 2 倍；帧率约 10fps。觉得慢随时切回 80。单片机不用动，只换 exe。
